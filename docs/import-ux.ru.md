# Импорт личных текстов: UX и границы доверия

Пользователь должен понимать, **какие его тексты** повлияют на ответы агента и **кому они могут быть отправлены**. Поэтому импорт проходит через четыре видимых состояния:

```text
Источник → Предпросмотр → Выбор и проверка → Локальный профиль
```

## Что делает пользователь

1. Даёт путь к экспорту или подключает источник. Wordmanner показывает объём, каналы, даты и способ определения авторства. Чужие сообщения не считаются образцами.
2. Выбирает чаты или другой срез данных и назначает ему язык и аудиторию: работа, друзья, семья и т. д. Эти срезы не смешиваются автоматически.
3. Открывает короткую выборку реальных исходящих текстов, исключает нехарактерные и чувствительные примеры по номерам. Малосодержательные реакции, пересылки и вероятно написанные с ИИ длинные тексты имеют низкий приоритет или пропускаются.
4. Применяет просмотренную выборку. До этого шага профиль не меняется. Пользователь может проверить количество образцов через `wordmanner samples inspect`.

Текущий CLI реализует этот поток для полного JSON-экспорта Telegram. Команды и ограничения описаны в [инструкции](telegram.md). Примеры из почты пока отбираются вручную; коннектор и такой же поток предпросмотра для почты — следующий отдельный этап.

## Приватность по умолчанию

- Оригинальный архив остаётся на месте. Wordmanner читает его потоком и не копирует в репозиторий.
- Предпросмотр содержит метаданные чатов, но не тексты сообщений. Подготовленная выборка содержит тексты и сохраняется в директории с правами владельца.
- Никакая команда импорта не вызывает модель. При использовании профиля в облачном агенте выбранные короткие выдержки могут попасть провайдеру этого агента. Это должно быть понятно до применения профиля.
- Фильтры контактов и ссылок уменьшают риск, но не заменяют просмотр человеком. В будущих коннекторах потребуется такой же этап выбора и явное указание внешних передач данных.
- Удаление образцов по источнику и полноценный аудит того, какой образец повлиял на ответ, остаются необходимыми возможностями перед широким выпуском.

## Как измерять удобство

Проверяем не только число кликов. Пользователь должен суметь ответить: «Почему этот текст попал в профиль?», «Как убрать его?», «Какие примеры агент увидит сейчас?». Для командных инструментов важны также понятные ошибки, повторяемость импорта и отсутствие скрытых изменений при предпросмотре. В интерактивной оболочке эти состояния можно объединить в мастер, сохранив тот же механизм отбора.
